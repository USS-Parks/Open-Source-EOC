## 3. Environment you inherit and how to run the gate

The test cluster is the approved project-local PostgreSQL 16 + PostGIS in
`deploy/test-runtime/out/` (see its README). It listens on 127.0.0.1:55439,
bootstrap DB `openeoc_test`. It is currently running and, as of this handoff,
**de-bloated**: 1369 orphaned `t_*` test databases were dropped, so startup and
recovery are fast again.

Start the cluster (idempotent) and set the gate env, in PowerShell from the repo
root:

```powershell
$testRoot = (Resolve-Path deploy/test-runtime/out).Path
& "$testRoot/pgsql/bin/pg_ctl.exe" -D "$testRoot/data" -l "$testRoot/postgres.log" -o '-h 127.0.0.1 -p 55439' -w start 2>&1 | Out-Null
$pass = [IO.File]::ReadAllText("$testRoot/test-password.txt").Trim()
$env:OPENEOC_DATABASE_URL = 'postgres://postgres:' + [Uri]::EscapeDataString($pass) + '@127.0.0.1:55439/openeoc_test'
$env:OPENEOC_CHROMIUM = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
$env:OPENEOC_TEST_BUILD_ROOT = "$testRoot/browser"
$env:OPENEOC_SHOT_DIR = "$testRoot/browser-shots"
$env:OPENEOC_DATA_DIR = "$testRoot/blobs"
```

**Gate per increment (fast, preferred):** typecheck + lint + only the tests the
change touches. This is the rhythm this session used and Basho endorsed after
objecting to full-suite runs on every micro-commit:

```powershell
pnpm -r exec tsc --noEmit    # all packages; catches cross-package type breaks
npx eslint .                 # warnings are errors
npx vitest run <the one or two affected .test.ts files>
```

**Full suite only at section milestones** (`pnpm check --maxWorkers=2`), not per
commit. `pnpm check` = tsc -> eslint -> license-scan -> check-links -> vitest.

Caveats:
- The RTK proxy mangles vitest stdout ("All parsing tiers failed"). Tee vitest
  output to a log and read the `Test Files` / `Tests` summary lines, or use
  `| Select-Object -Last N`.
- Flaky Windows worker crash `3221226505` (0xC0000409) at worker startup on a
  random file is environmental; re-run, do not treat as a code failure.

## 4. Hazards learned the hard way (do not repeat)

- **Never kill or restart the shared test cluster mid-run.** Doing so triggers
  PostgreSQL crash recovery, whose full-directory fsync is slow and, on this
  Windows host under load, dies with exception `0xC0000142` and loops. If a
  cluster comes up slowly, let recovery finish; watch `postgres.log` only, do
  not fire connection attempts during recovery (a connecting backend that fails
  DLL-init makes the postmaster panic and abort recovery). A quiet single start
  recovers cleanly.
- **The freshDb leak is fixed but stays only if you keep the teardown.** Do not
  remove `server/src/__tests__/globalSetup.ts` or its `globalSetup` wiring in
  `vitest.config.mjs`. If the cluster ever bloats again, drop leaked DBs with
  psql `\gexec`: `select 'drop database if exists '||datname||' with (force)'
  from pg_database where datname ~ '^t_[0-9a-z]{10}$'`.
- **Write protocol (CLAUDE.md):** use the Edit tool for existing files. Never
  `sed -i`, `perl -i`, or shell redirects onto workspace files. New files over
  40 lines go to the scratchpad first, verified with `wc -l` + `tail`, then
  copied in. PowerShell `Remove-Item`/`Set-Content` can trip a path guard; avoid
  them, and prefer `Tee-Object -FilePath` (it overwrites) over deleting first.
- **Staging:** stage files individually by path, never `git add .`/`-A`; inspect
  `git diff --cached --stat` before every commit.

## 5. Design and workflow rules (verified adhered to this session)

- **Commit hygiene:** plain-speak subject/body; end every message with
  `Copyright Basho Parks - 2026`; NO `Co-Authored-By`, AI attribution, tool
  signatures or emoji. The `.githooks/commit-msg` hook enforces this; keep
  `git config core.hooksPath .githooks`. Never `--no-verify`.
- **One unit of work = one focused commit.** A roster prompt may be several
  commits; that is fine. Append a receipt per unit to
  `docs/VEOC-EXECUTION-LEDGER.md` (Baseline SHA, Change, Evidence, Gate,
  Boundary, Ending commit). Report red as red; name scope boundaries.
- **No source slop (CANON section 11):** no `Session N` / scaffold / "would...in
  production" / dangling references. `(VEOC-NN)` and `(Handoff N)` comments are
  approved by Basho and match the repo convention; keep using them.
- **FOUO model (memory `eoc-fouo-access-model`):** no public/anonymous facet.
  Authorized members AND valid mutual-aid guests get unrestricted incident and
  dashboard access; only unauthenticated/unauthorized are denied. Never build a
  public read path. This is the whole point of VEOC-80.
- **Gated external data:** no outbound service registration, API keys, or network
  fetches without Basho's separate authorization (CLAUDE.md). Several remaining
  prompts name external sources (FEMA NFHL flood, Overture buildings, IPAWS).
  Deliver the reusable pipeline and record the exact external data as a named gap

  live fetch; loading stays on the existing push/poll seam.

  `canonical-style-bible`) are an after-VEOC-85 styling PSPR, not this roster.
  Build 81-series structure so it will not fight that later pass, but do not
