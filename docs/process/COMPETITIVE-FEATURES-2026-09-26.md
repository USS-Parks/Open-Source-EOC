## 2. Feature matrix

Status key for Open Source EOC: **have** (built and verified), **partial** (some support, real gap), **missing**, or **MPn/VCn** (covered by a unit already in the running Map and Dashboard Parity plan, or a candidate already logged in the Veoci research's VC list awaiting a roster).

| Feature | Vendors with it (2025 to 2026 evidence) | Open Source EOC status | Lower-friction offline approach |
|---|---|---|---|
| One-click / executable incident activation from a plan | Juvare (WebEOC Nexus incident creator), Esri (EMO one-click activation), Veoci (Plans) | **VC-09/VC-01** (candidates logged, not built) | A local plan object with versioned sections, no cloud call, launches boards/tasks/notifications in one action; no per-seat license to unlock it |
| AI assistant: natural-language search and summarization over incident data | Juvare (JAI), Esri (AI assistants in Survey123, Business Analyst, translation), Veoci (VIA) | **missing** (VC-36, parked pending a decision) | A small local model (llama.cpp/Ollama class) run as a sidecar, draft-only output with a human author, no data leaving the box; avoids the "what model, what host" question all three vendors leave vague |
| AI-assisted damage assessment from a field photo | Juvare (Crisis Track AI), Esri (Survey123 AI image analysis) | missing | A local vision model classifies severity/type from the photo already captured offline in the existing damage form; the human still confirms before the record is final |
| Two-way SMS / inbound field reporting with no app or login | Juvare (ICS 214 by text), Veoci (two-way SMS check-ins) | **partial, VC-16 candidate** (outbound SMS works; inbound not read) | A telephony sidecar (jambonz or Somleng, both MIT) reads the reply and posts it as a structured record; works when data connectivity is down but SMS gets through |
| Geo-targeted alerting: draw an area, auto-select recipients inside it | Juvare (Geoalerting) | missing | Needs a location field on contacts (most already have an incident-scoped address); a point-in-polygon check against the drawn area, no new dependency |
| Utility outage data as a reference layer / feed | Juvare (PowerOutage.com partnership) | missing | PowerOutage.com publishes free county-level counts; add it as one more preset in the existing feed engine, cached like the other live feeds for offline use |
| Public damage self-report form / hub site | Esri (Damage Assessment Hub), Juvare (Crisis Track public forms), Veoci (public forms) | **absent by decision, VC-34** (collides with the FOUO standing decision) | An external Apache-2.0 form server (for example ODK Central) feeding the existing moderated, token-authenticated intake keeps the FOUO boundary intact while adding the capability |
| Public dashboard / map snapshot for shelter or evacuation status | Esri (Emergency Shelter Management public app), Veoci (Honolulu pattern) | **absent by decision, VC-35** | A published, read-only snapshot export (GeoJSON, PMTiles, PDF) to a host outside the FOUO boundary, refreshed by an authorized user, rather than opening the platform itself |
| Satellite (SAR) hazard imagery ingestion (flood depth, building-level) | Juvare (ICEYE integration) | missing | Free Sentinel-1 SAR products (ESA, public domain equivalent access) into the existing feed/imagery pipeline; commercial ICEYE-grade fusion is out of reach but a raw SAR layer is not |
| Cross-jurisdiction shared COP for a large planned event | Juvare (Exchange for the World Cup) | partial (ADR-0006 federation exists; not exercised at event scale) | Federation already supports organization-scoped participation; a multi-incident "event" wrapper over several federated incidents is the missing piece, not a new protocol |
| AI-assisted after-action pattern mining across incidents | Juvare (JAI in AAR, cross-incident capability-area analysis) | missing (AAR itself is **MP13**) | A rule-based rollup (count corrective actions by capability area, by responsible organization) gets most of the value without a model at all |
| Natural-language form / survey builder | Esri (Survey123 assistant), Veoci (VIA form generation) | missing (**VC-32** candidate: visual builder or ODK Web Forms) | Lower priority than the AI-photo and AI-chat items; the existing declarative smart-form schema is already no-code, just not conversational |
| Commercial real-time threat-intel feed (Dataminr-class breaking events) | Esri (Velocity + Dataminr) | not applicable by design | A commercial feed is a recurring cost and a vendor dependency; the public-feed set (NWS, USGS, NIFC, NOAA) already in **MP10** covers the same hazard classes without the license |
| Utility-specific damage workflow (asset-linked outage and damage records) | Juvare (Crisis Track for Utilities) | partial (generic damage module exists; no asset linkage) | Add a `record_ref` from a damage record to a critical-facility/asset record, which the schema already supports; no new engine |
| FEMA Public Assistance cost capture (force account labor, equipment, materials) | Juvare (FEMA Submissions), Veoci (FEMA Public Assistance package) | **partial, VC-10 candidate** | Hours already exist in shifts and check-ins; equipment hours already exist in the resource pool; the missing piece is a rate table and a roll-up to PA categories A to G |
| AI governance / certification for an AI feature (ISO/IEC 42001) | Juvare (audited November 2025 per company statements) | not applicable | A documentation exercise, not a build; relevant only once an AI feature (VC-36) is un-parked |

## 3. Ranked shortlist: the 15 missing features that matter most to an EOC

Ranked by how often competitors promote the feature across this window and how central it is to daily EOC work, not by ease of build.

1. **One-click / executable incident activation from a plan.** Large. All three vendors lead with this; it is the single biggest labor-saver for a thin staff and the one primitive OpenEOC's own Veoci research already flags as the most valuable gap (VC-09).
2. **AI assistant for natural-language search and summarization over incident data.** Large. The dominant 2025 to 2026 promotion from every vendor (JAI, ArcGIS AI assistants, VIA); central to command-staff situational awareness under time pressure.
3. **AI-assisted damage assessment from a field photo.** Medium to large. Directly tied to FEMA reimbursement speed, the highest-stakes recurring task for a small jurisdiction after any disaster.
4. **FEMA Public Assistance force-account cost capture.** Large. Not flashy, but it is where a thin staff loses real reimbursement money; both Juvare and Veoci sell it as a named package.
5. **Public damage self-report intake.** Large (gated). Esri, Juvare and Veoci all ship it; central to a fast, accurate damage picture, but requires a Basho decision on the FOUO boundary before any build.
6. **Two-way SMS / inbound field reporting with no login.** Medium. Directly useful when data connectivity fails but SMS survives; both Juvare and Veoci promote it as a signature capability.
7. **Public shelter / evacuation status dashboard.** Medium (gated). Esri's new Emergency Shelter Management solution and Veoci's Honolulu pattern both center this; matters most to the public-information mission.
8. **Satellite SAR hazard imagery (flood depth, etc.).** Large. Juvare's ICEYE integration was one of its most-promoted 2026 items and Florida's adoption shows real operational pull; central to flood-heavy jurisdictions.
9. **Geo-targeted alerting (draw an area, auto-notify).** Small to medium. A precise, well-promoted Juvare feature that closes a real gap in call-down targeting.
10. **AI-assisted after-action pattern mining.** Medium. Turns AAR data from an archive into a planning input, which Juvare demonstrates concretely with JAI.
11. **Utility outage data as a reference feed.** Small. Cheap to add, directly promoted by Juvare's PowerOutage.com partnership, and useful for any jurisdiction with grid-dependent facilities.
12. **Cross-jurisdiction shared COP for a large planned event.** Medium. Juvare's World Cup deployment is a strong proof point; OpenEOC's federation groundwork makes this an extension, not a new capability.
13. **Utility-specific damage workflow (asset-linked records).** Medium. A specialization of an existing module that Juvare promotes as a distinct product line.
14. **Natural-language form / survey builder.** Medium. Promoted by both Esri and Veoci, but lower urgency than the AI-chat and AI-photo items since the underlying form schema is already no-code.
15. **AI governance documentation for any shipped AI feature.** Small. Not a feature an operator asks for directly, but Juvare's ISO/IEC 42001 audit signals that a documented control mapping will matter once VC-36 (local AI) is un-parked.
