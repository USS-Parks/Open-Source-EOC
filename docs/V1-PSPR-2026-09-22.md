## 2. Deployable status today

### 2.1 What can be stood up

**Windows desktop (the stronger path).** A per-user installer stages portable
Node, PostgreSQL with PostGIS, the built web app and the server sources with a
signed per-file manifest. First launch prompts for the admin identity and
jurisdiction, binds to loopback, runs migrations as owner and serves under the
runtime role with row-level security always on. Uninstall preserves data.
Backup is "stop the profile and copy the directory." It is not a transferable
bundle: Node, PostgreSQL, a browser and the map archives are machine
prerequisites (`docs/WINDOWS-DESKTOP.md` 123 to 127).

**Docker (the documented server path).** `deploy/install.sh` generates
secrets, brings up PostGIS and the API, and waits for health. It ships no web
front end (the nginx service is commented out at `deploy/docker-compose.yml`
51 to 57), no TLS (plain HTTP on 8080), no first-user bootstrap (the README
says use psql), and its documented first boot runs on the owner connection
with row-level security off and a console warning (`server/src/main.ts` 26,
35 to 42).

### 2.2 What is single-process by construction

Six module-scope maps: the flood limiter, the login backoff, the board sync
hub, the board event bus, the OIDC pending-login map and the per-request
dashboard cache. A second node splits live sync, doubles the credential
guessing budget and breaks the OIDC callback. No trusted-proxy setting, so
behind any reverse proxy every client shares one rate bucket. The comment that
promises a shared store "with horizontal scaling" refers to a unit that
closed without one. The honest statement is single node, and R1 already
scopes 150 users to one instance.

### 2.3 What is missing outright for an operator

Fastify runs with `logger: false`; there are no request logs, no structured
logs, no metrics endpoint, no alerting hook. No log rotation, no data
retention or purge (the audit table cannot be trimmed by design). Audit export
is unpaginated JSON. No email, SMS, voice or push notification; the three
channels are in-app, webhook and ntfy. No identity administration screen: a
county admin creates people and assigns roles with curl. No WebEOC migration
path. No key rotation for the envelope secret. No secret scan and no
dependency advisory scan in the gate. No `SECURITY.md`. No disaster-recovery
runbook, no restore drill on record, no version pinning or upgrade
compatibility statement. Training material stops at the eight role guides,
which are good and buried.

### 2.4 What will fail during a long activation

Ranked by the code scan, all verified at `d2ca863`:

1. `server/src/sync/hub.ts` 50: one Yjs document per board and incident, held
   for process lifetime, never evicted, never compacted; `open()` re-encodes
   the whole board and rescans records on every connection.
2. `server/src/sync/hub.ts` 204 and `server/src/boards/routes.ts` 186, 218:
   webhook delivery awaited inside the write path, five seconds per target,
   no queue, no retry. One slow endpoint stalls the board.
3. `server/src/notify/routes.ts` 68: the notifications list, polled every
   eight seconds by every user, unpaginated, capped at 100, joined on a cast
   that defeats the primary-key index. Notification 101 is unreachable.
4. `server/src/boards/service.ts` 529: the board view loads every record and
   filters in JavaScript; accepted as headroom at VEOC-38.
5. `server/src/auth/service.ts` 119 to 131: about six database round trips
   per authenticated request, then the handler's own transaction; no
   principal cache over the fifteen-minute token life.
6. WebSocket: no `bufferedAmount` check, no auth deadline, default 100 MiB
   payload, unbounded update string, no heartbeat (`server/src/sync/routes.ts`
   60, `server/src/app.ts` 95 to 113).
7. `server/src/auth/rate-limit.ts` 14: login backoff map keyed by
   attacker-supplied email, never pruned.
8. No scheduler exists. `run-scheduled`, `run-due` and feed polls are
   endpoints only; nothing calls them. Scheduled briefings and notification
   rules never fire in a deployment.
9. Outbound fetches without timeout in the collab and IPAWS connectors.
10. Base64 JSON upload, three copies of a 30 MB payload in heap per upload.
11. `xlsx@0.18.5`, the last npm release, with two open advisories, parsing
    operator-uploaded workbooks.
12. `markDelivered` in `server/src/federation/service.ts` 105 is never
    called; the outbox grows forever and re-serves the same batch every poll.

### 2.5 Threat-model rows whose control does not exist

- B9, two-person rule on a live IPAWS send: `server/src/ipaws/` enforces
  admin-only and nothing more.
- B7, webhook URL allowlist per jurisdiction and per-rule rate caps: HMAC
  signing exists; the allowlist and caps do not. An authenticated member who
  can create a rule gets a server-side request from inside the EOC network.
- B5, the plugin sandbox: no code behind it.

## 3. Distance from v1

### 3.1 What v1 means in this plan

Version 1.0 is not absolute parity. It is the release a county can install
from one command or one installer, operate through an activation without an
engineer present, back up and restore on a schedule, upgrade without fear,
secure to the floor its alerting authority demands, and evaluate side by side
with WebEOC on the capabilities counties actually buy WebEOC for. The gates
are enumerated in section 8. Absolute parity claims remain governed by
`86+D35`'s wording and are made only where evidence exists.

### 3.2 The gap, ranked by what blocks an operator first

1. **Operability.** Logging, metrics, retention, audit export, runbooks.
   Nothing on any roster. Wave W2 and W6.
2. **Survivability of one activation.** Section 2.4 items 1 to 8. Wave W2.
3. **Install and secure by default.** Web service and TLS in the compose
   stack, bootstrap script, refuse to serve with RLS off, secret and advisory
   scans in the gate. Wave W2 and W6.
4. **Reachability of what is built.** Wave W3: the 94 unwired routes,
   starting with identity administration, audit chronology, damage
   assessment, staffing, facilities, IPAWS enablement and export.
5. **Notification reach.** Email and SMS, contacts, mass notification. Wave
   W4. A WebEOC shop will not evaluate a platform that cannot page a duty
   officer.
6. **Identity floor.** MFA at minimum, SAML if the county's IdP demands it.
   Basho's decision, then wave W2.
7. **Board and reporting depth.** Cross-board lookups, record permissions,
   delete and archive, record history, CSV and Excel both ways, grouped and
   kanban views, a report builder. Wave W4.
8. **Data at scale.** Vector tiles for operational layers, clustering,
   pagination everywhere. Waves W2 and W4.
9. **Field depth.** Line and polygon capture, barcode, media, the remaining
   XLSForm types. Wave W4.
10. **Acceptance evidence.** The integrated exercise, the operator
    comparison, the real-hardware load run, the second-machine transfer, the
    manual screen-reader pass, the pilot. Wave W7 and Basho's inputs.

  file and applies the home `.prettierrc` (single quotes, no semicolons). It
  reflowed two committed files in `aa2661e`. **Closed by `W0.1`:** the hook
  resolves the touched file's git root and supplies that repository's
  `.prettierignore`; the pre-commit gate rejects a staged JavaScript or
  TypeScript file whose quote style flips.

  removed 116 of them. **Closed by `W0.1`:** the repository pre-commit gate
  scans staged additions for the audit's patterns (`VEOC-nn`, `Dnn`, `Wn.n`,
  `Mn`, `81c`, `P-...`) in comments and test titles, not in data.

  during a run. Full-suite runs at `--maxWorkers=2` on this host produced

  files pass in isolation. Milestone gates run with `--maxWorkers=1` and the
  `gate` tag, and a timeout in `freshDb()` is retried once in isolation
  before it is called red.
- **HZ-D, two actors on one checkout.** Basho's own sessions produce
  untracked material at the root (`Reference Screenshots/`,

## 10. Execution model

- Roles, modes, lanes, the zipper, unit lifecycle, failure handling and the
  templates are those of the Master PSPR sections 7 and 11, unchanged.
- W0 runs in the canonical checkout by Astra alone; it touches shared
  documents and the git index.
- W1 runs one unit at a time because it moves files that other units own.
- W2 and W3 fan out: engine lanes for W2 (`W2.0`, `W2.1`, `W2.3`, `W2.8` in
  parallel; `W2.2`, `W2.4`, `W2.9` after their dependencies) and presentation
  lanes for W3 once `W2.3` and `W2.5` have landed, since every screen consumes
  cursors and the admin surface consumes the principal changes.

- W5 and W6 are mostly solo units in the canonical checkout because they
  touch the build, the deploy tree and the root manifests.

- Milestone gates: after W0, W1, W2, W3 and W4, the full suite on `main`
  with the gate tag at `--maxWorkers=1`; after a green gate Astra reports the
  unpushed range and stops, and pushing is Basho's instruction to give.

  document, its evidence level, and the guide section it updates. A unit that
  adds a route adds it to the contract in the same commit or the route-table
  test fails.
